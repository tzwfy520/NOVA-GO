# 交互适配（collector.device_defaults）现状分析与设计建议

## 1. 背景与范围

本文聚焦 `configs/config.yaml` 中 `collector.device_defaults` 章节所描述的“设备交互参数适配”，梳理它在项目中的加载方式、参数流转路径与实际生效点，并分析当前实现方式的优缺点，给出更合理的设计方式与修改建议（本轮不调整代码）。

交互适配的目标通常包括：

- **提示符识别**：判断一条命令的输出何时结束。
- **分页处理**：自动关闭分页或在出现分页提示时自动翻页。
- **提权流程**：如 Cisco `enable`、Linux `sudo -i`。
- **交互节奏/超时**：命令间隔、单命令超时、静默判定、提示符诱发等。
- **输出过滤**：过滤分页提示行（如 `--more--`）或噪声行。
- **错误提示识别**：基于输出特征标记命令失败（非致命或致命）。
- **配置模式切换**：进入/退出配置模式（Deploy 场景）。

## 2. 配置结构概览

以 `configs/config.yaml` 为例，`collector.device_defaults` 至少包含以下字段族（不同平台可选配置）：

- **提示符**：`prompt_suffixes`
- **分页**：`disable_paging_cmds`
- **提权**：`enable_required` / `enable_cli` / `enable_except_output`
- **交互行为**：
  - `interact.auto_interactions[]`：输出触发 → 自动发送
  - `interact.error_hints[]`：错误提示前缀集合
  - `interact.case_insensitive` / `interact.trim_space`
- **输出过滤**：`output_filter.prefixes/contains/case_insensitive/trim_space`
- **超时/节奏**：`timeout.timeout_all` + `timeout.interact_timeout.*`
- **配置模式**：`config_mode_clis` / `config_exit_cli`
- **其他**：`skip_delayed_echo` / `long_output_commands`

参考配置位置：[config.yaml:collector.device_defaults](file:///Users/wangfuyu/PythonCode/SSH-GO/configs/config.yaml#L36-L232)。

## 3. 配置加载与合并（非常关键）

### 3.1 实际生效的 device_defaults 不仅来自 config.yaml

启动加载时，除了 `configs/config.yaml`，系统还会读取 `configs/auto-ssh.yaml` 并将其作为**基准**覆盖到 `config.Collector.DeviceDefaults` 中：

- 逻辑位置：[config.Load](file:///Users/wangfuyu/PythonCode/SSH-GO/internal/config/config.go#L170-L293)
- 合并位置：[config.go: auto-ssh.yaml 合并](file:///Users/wangfuyu/PythonCode/SSH-GO/internal/config/config.go#L264-L286)

合并策略（当前实现）：

- 先用 `auto-ssh.yaml` 的 `collector.device_defaults` 填充 `merged`
- 再用 `config.yaml` 的同名平台项补齐 `merged` 缺失的平台
- 若同名平台同时存在：**仅保留 `config.yaml` 中的 `long_output_commands`（当 auto-ssh 未声明时）**

这意味着：即使 `config.yaml` 中配置了某平台的交互细节，只要 `auto-ssh.yaml` 中同平台也配置了对应字段，运行时基本以 `auto-ssh.yaml` 为准。

## 6. 当前实现方式的优缺点

### 6.1 优点

- **配置驱动**：提示符、分页、提权、节奏、过滤等关键交互差异基本都可通过 YAML 调整。
- **统一执行入口（部分场景）**：Collector/Backup 通过 `InteractBasic` 统一了交互优先与非交互回退，降低了业务侧重复实现。
- **交互鲁棒性增强**：在 `ssh.Client.ExecuteInteractiveCommands` 中加入了提示符诱发、静默完成、enable 密码回退、长输出命令特殊处理等机制。
- **输出后处理集中**：输出过滤与预命令过滤在服务层统一处理，业务层无需关心分页提示等噪声。

### 6.2 缺点与风险

- **平台匹配策略不一致**：同一 platform 值在不同功能点上命中不同配置（精确匹配 vs 硬编码前缀 vs 通用前缀），容易出现“部分适配生效、部分失效”的隐性问题。
- **device_defaults 字段存在双轨结构**：`AutoInteractions/ErrorHints` 既可能出现在顶层字段，又可能出现在 `interact` 内部；不同服务读取路径不同（Collector 兼容更多，Deploy 基本只读 `interact`），增加配置心智成本与兼容风险。
- **auto-ssh.yaml 覆盖 config.yaml 的惊讶性**：主配置文件中写的 platform 细节在运行时可能被 auto-ssh 覆盖，排障时容易误判“配置不生效”。
- **交互选项未完全对齐配置语义**：`interact.case_insensitive/trim_space` 只在部分错误提示检测中生效，AutoInteraction/EnableExpectOutput 等匹配行为并未完全按该语义统一。
- **预命令结果过滤存在边界反直觉**：当用户命令列表只包含预命令（如只执行 `enable`），过滤后为空会回退返回原结果，可能把内部预命令暴露给调用方（见 `filterInternalPreCommandsBase` 的空结果回退分支）。

## 7. 更合理的设计方式（建议）

### 7.1 统一“平台配置解析器”（核心建议）

引入一个单点解析函数（概念上）：

- 输入：`platform string`
- 输出：`ResolvedInteractProfile`（已合并 default + platform + 全局基线后的最终配置）

并明确它在所有服务中复用，避免出现三套不同的“平台匹配/合并”策略。

建议在解析器内部统一：

- 平台 key 规范化：`strings.ToLower(strings.TrimSpace())`
- 匹配策略：优先精确匹配，其次前缀匹配（可配置或仅对白名单启用），最后回退 `default`
- 字段族合并：`global ssh baseline` → `device_defaults.default` → `device_defaults.<platform>` → `request overrides`（如未来需要）

### 7.2 将“交互适配配置”结构显式化

建议形成单一结构体（概念）包含以下子模块（避免字段散落且重复）：

- `Prompt`：suffixes、deviceName 参与规则、configPrompt 判定规则
- `Paging`：disable commands、auto page rules（more/confirm）
- `Privilege`：enableRequired、enableCLI、expectOutput、password source（login/enable）
- `Timing`：interval、perCommandTimeout、quiet rules、inducer、fallback
- `Filter`：output_filter
- `ErrorDetect`：error_hints 与匹配策略
- `ConfigMode`：enter/exit cmds、conditional-exit 策略

好处是：

- 明确不同字段族的职责边界
- 方便在交互执行器里一次性消费，减少散落取值与逻辑分叉

### 7.3 明确 auto-ssh.yaml 的角色

目前 auto-ssh.yaml “覆盖”主配置的策略更像“内置默认库”，但覆盖方向与直觉相反。

更合理的选择一般是二选一：

1. **auto-ssh.yaml 作为内置默认库**：先加载 auto-ssh，再用 config.yaml 覆盖（主配置优先生效）。
2. **auto-ssh.yaml 作为可选补充配置**：仅在 config.yaml 未提供 device_defaults 时才加载 auto-ssh。

无论选哪种，都建议让“最终生效的 device_defaults 来源”可被清晰地观测（例如在 /api 中返回时携带来源标识或 dump）。

### 7.4 对齐匹配语义（case_insensitive/trim_space）

建议统一匹配语义：

- `AutoInteraction`、`ErrorHint`、`EnableExpectOutput` 三者使用同一套 “trim + casefold + contains/hasPrefix” 策略，并由配置明确选择。
- 或者将配置收敛：把 `case_insensitive/trim_space` 固定为 true（简化配置），避免给人“可配但不生效”的错觉。

## 8. 修改建议清单（不改代码，仅给建议）

- 建议 1：把“平台匹配/兜底/合并”收敛到单一函数，并在 Collector/InteractBasic/Deploy/Filter 统一复用。
- 建议 2：消除 `PlatformDefaultsConfig` 中 `AutoInteractions/ErrorHints` 的双轨字段，统一只保留 `interact.*`，并提供一次性的兼容迁移。
- 建议 3：移除 auto-ssh.yaml文件和相关生成逻辑，所有设备默认配置都在 config.yaml 中。
- 建议 4：补齐或移除 `interact.case_insensitive/trim_space` 的配置语义，使其对 AutoInteraction/EnableExpectOutput/ErrorHints 一致生效。
- 建议 5：修正预命令过滤的“空结果回退”策略，避免在“仅预命令场景”暴露内部命令结果。
